# 验收矩阵与已知限制

这是 **V1 试用范围**，不是宣告全量 P00–P12 已验收。目标基线是官方 OpenWrt 24.10.5 x86/64；IPK 不代表路由器镜像，也不证明其他架构能运行。

## P00–P12 对照

| 编号 | 本次交付 | 未完成或待实机检查 |
|---|---|---|
| P00 工程和契约 | C/libubus/uloop、procd、UCI、安全缺省、OpenWrt 包；21 个 RPC 有明确能力和权限 | 无业务的预留写 RPC 明确返回 NOT_SUPPORTED |
| P01 发现、入网与 mTLS | 管理接口 UDP 候选、离线 CA、每节点叶证书、人工指纹授权、认证心跳、授权持久化 | WPS/按键、二维码、LLDP 自动入网、线上签发、自动角色变更未做 |
| P02 回程和自愈 | 在已存在的有线网或单跳 WDS 上运行，不触碰回程 UCI，避免远程发布时误改管理链路 | 无 batman-adv/802.11s 自动编排、链路评分、选父节点或多跳恢复；WDS 仍需兼容硬件实机 |
| P03 漫游 | 为显式 WPA2 AP 开关 k 邻居/信标、v 和 r，本地简单 FT（FT 可选） | 未实现 11k 全网邻居表主动同步、BTM 引导/强断、频繁漫游平衡、WPA3 和逐终端降级；切换时延待测 |
| P04 配置事务 | 签名、版本、摘要检查、暂存和原子文件替换，本机失败/中断恢复，逐台确认与失败暂停 | 不做远端撤销、整批全局回滚或跨 wireless/network/firewall 提交，不做分布式原子事务 |
| P05 终端与分组 | 可查询能力状态，不伪造设备数据 | 终端识别、租约/FDB 聚合、别名、随机 MAC 聚合和固定 AP 未做 |
| P06 策略 | 只修改已选普通业务 AP，拒绝含自定义认证和 VLAN 的目标 | 访客/IoT 三网、家长控制、QoS、DNS/DPI 未做 |
| P07 LuCI | 六页面、读写分离、手动刷新保留草稿、角色及权限门禁 | 仅概览/节点/无线/诊断具有本版实际能力；无虚构物理图、移动端或四套主题 |
| P08 OTA | 安装包的 OpenWrt sysupgrade 保留清单 | 不执行刷机、Bootloader 操作、A/B、签名 OTA 或回退；待具体机型 |
| P09 诊断 | 预检、无密钥的结构化诊断、128 条内存事件 | 无链路评分、资源统计、证书告警、完整导出包或 7×24 实测 |
| P10 安全 | 管理接口绑定、mTLS 与双向叶指纹限制、默认无 WPS/RPC 最小写权限、版本/摘要与签名、0600 身份/配置记录、不拼接命令 | 无共享消息 HMAC/时间戳层（控制面用短 mTLS 会话与版本，发现不认证）、自动证书轮换/CRL、安全启动或生产渗透验收 |
| P11 测试 | 源码与 UI 测试、SDK 编译、真实 socket 传输与无线文件事务、OpenWrt 用户空间安装冒烟 | 射频、物理回程、掉电、跑机、压测、抓包和 OTA 需要目标板 |
| P12 集成 | 可复现的官方 SDK x86/64 脚本与 CI、可将两个包移植到目标 SDK、安装文档 | 不发布可刷或签名量产固件；三频/双频正式 profile 需机型、闪存布局和现有固件版本 |

## 已执行的验证

- Windows 上运行 `python -m unittest discover -s tests -v`、LuCI [DOM/RPC 冒烟测试](<../luci-app-meshd/tests/smoke.cjs>)、服务脚本静态语法和独立 PKI 签发自检；Linux x86_64 虚拟机复跑前两项和 `make -C tests test`。
- 用 [固定版本的 SDK 构建脚本](<../scripts/build-sdk.sh>) 实际交叉编译两个 IPK。核对守护进程 ELF x86-64/musl 与 libubus/libubox/libuci/mbedTLS ABI、IPK 的依赖/配置保留和 LuCI 文件清单。
- 在隔离 Linux 网络命名空间中，使用官方 SDK 产出的库和 [真实 UDP/mTLS 测试程序](<../package/meshd/tests/test_transport.c>)，测试发现网络隔离、错误网关指纹、未授权叶证书、最大允许帧及签名响应。使用独立测试证书，不涉及现场设备。
- 以 OpenWrt 24.10.5 libuci/mbedcrypto 在临时目录验证无线预检和事务，覆盖特殊字符、保留非管理 AP 与 WDS、冲突时拒绝覆盖、恢复原始字节。
- 在官方 24.10.5 x86/64 用户空间的隔离环境中，`opkg` 安装两包、启动 `ubusd` 与 `meshd`、检查 21 项 RPC；默认 `disabled/candidate`、`transport=false`、未授权写和未启用方法均不执行。该环境不含真机无线与 procd 的完整启动链。

### 目标路由器验收

1. 用 [部署手册](<deploy.md>) 搭两节点有线测试网。对照网关和节点指纹：候选发现后必须人工授权，授权后才可认证在线；换成另一枚未授权证书应无法建立受信会话。网关去掉授权后应不再接受心跳。
2. 在网关发布一个临时测试 SSID。用 `ubus call meshd config_status` 和 `ubus call meshd topology` 确认本地确认后节点版本收敛。分别用真实终端连接两个 AP 并验证 DHCP、访问网关与上网。
3. 保留维护口，在隔离测试环境让某一节点的 hostapd 停止应答，观察超时、本机恢复、网关暂停和已有其他节点保持。配置恢复后先用 SSH/网线核对 UCI 和 AP 再重发。不要在生产主网故意断服务。
4. 断开节点回程，确认控制面约 15 秒判离线，接回后重新认证。测量时独立记录业务 ping；该测试验证状态，不意味着插件会找备用路径。
5. 测 k/v/r 前后实际漫游：单独记录终端/驱动版本、AP 信道、包间隔、切换丢包和视频表现。单跳 WDS 另测管理 VLAN 透传和断链行为；测试时不要把有线路径与 WDS 并行桥接成环。
6. 正式接入前做掉电、长期运行、flash 写入、资源占用和设备兼容性验证。文档中的目标（250 台终端、<50 ms 漫游、≤5 s 自愈、12 MB 内存预算等）没有在本次硬件实测，不能作为验收结论。
